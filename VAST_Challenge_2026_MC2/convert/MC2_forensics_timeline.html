1-Second .doc → .txt Metamorphosis

机密文件在一秒内被暴力转化为乱码帖子 — 不经过任何格式解析

关键证据：Emma Agent 在 23:02:00 读取 meeting_notes.doc，23:02:01 创建 SwiftWren.txt（30KB）。
仅 1 秒 — MS Word 二进制 → 纯文本，无格式转换步骤。OLE2 头部特征暴露，导致帖子呈现乱码。
→ 这不是加密，是原始数据提取的副作用。攻击者意在直接公开原始内部文件。

漏洞 1+2：无授权委派 + 盲目转发

queue_subordinate_task 零授权字段 — 任何 Agent 可向任何 Agent 委派任务，中间节点不读不验直接转发

漏洞 1：无授权

queue_subordinate_task 格式中零 auth/token/permission 字段。
全系统 17,038 次委派，零条需要接收方确认。
61% 的跳数跨越部门边界。
IT Helpdesk 员工 Agent 可反向委派 IT 负责人 Agent。

漏洞 2：盲目转发

中间 Agent 收到 task=read_file 后不读取文件，直接转发。
SwiftWren 中 17/18 个转发 Agent 从未读取指令文件。
235 次机械转发，无审计无确认。
→ 转发 = 无脑搬运，不看不验

漏洞 3：Agent 配置完整性盲区

系统审计 Runtime Logs，不审计 Configuration Integrity — 攻击在日志盲区完成

被篡改的 3 个 Agent：
John Agent — 植入硬编码触发协议（收到 *_further_instructions.md → t+1s check → t+2s post → t+3s delete）
Noah Agent — 预设定时任务（May 10 23:02 自主读取 strategic_directions.doc，Noah 本人全天零 assign）
Chloe Agent — 植入隐藏线程（深夜读取高管 Agent 配置 + 参与链转发，Chloe 本人全程零操作）
→ 全系统无任何 Agent 配置 write/modify 事件。配置层操作在日志中完全不可见。

漏洞 4：Agent 可绕过人类直接对外发帖

5 秒内完成 check → post → delete 全流程 — 无需人类审批

正常帖（105 次）

发起者：person:...（人类）
字段：content（手写文本）
路径：人类编写 → 发布

异常帖（3 次）

发起者：Agent/person:john_windward
字段：content_source（文件引用）
路径：Agent 自动读取文件 → 发布 → 删证据
5 秒完成，人类从未经手内容

全系统 108 次 saidit_post，仅 3 次由 Agent 发起 — 全部是异常帖。
→ HiddenOrca.txt | MellowOtter.txt | SwiftWren.txt → SaidIt general 论坛，公开可见

漏洞 5-7：配置可读 · 文件无创建审计 · 帖子无法管理

辅助漏洞 — 让攻击更容易，让追溯几乎不可能

漏洞 5：配置任意读取

全系统 1,098 次 Agent 配置被读取。
攻击者借此了解目标 Agent 行为模式，设计精确攻击向量。
Chloe Agent 读 Noah 配置 4 次
Gabriel Agent 读 John/CEO/COO 配置

漏洞 6：文件无创建审计

HiddenOrca 两个文件在数据中零创建记录。
文件可被创建、使用、删除，系统不记录创建者。
攻击者可在数据窗口前植入文件不留痕迹。

漏洞 7：无内容管理

全系统无 delete_post
block_user report moderate
SaidIt 帖子一旦发布，无法删除或管理。
攻击者只需删本地文件，帖子永久存在。

推荐干预：SaidIt content_source Gate

唯一的单点阻断 — 覆盖 3/3 异常帖，零误报

干预逻辑：Agent saidit_post 请求 → details 包含 content_source？
→ 是：要求人工审批 / 阻断 / 高优先级告警
→ 否：正常发帖路径

为什么选这个点：覆盖 3/3 已知异常帖 | 正常帖（105次）不使用 content_source，零误报 | 最靠近外部危害边界 | 不需要关闭 Agent 系统
