一个文件源 Agent 流程如何越界发布到 SaidIt

本页先建立正常行为基线，再隔离目标异常：John Windward 的 Agent 在 2046 年 5 月 17 日 04:21 UTC-7 向 SaidIt 发布了一条文件源消息。页面使用来自 MC2 data.json 和 org_chart.json 的计数、比例和可追溯证据。

结论：一个内部文档被打包为代号文本文件，作为 Agent read_file 任务传播，通过 saidit_post(content_source) 发布，随后被清理。相同机制共出现三次。

中文阅读版用于本地讲解和组内讨论；正式提交仍以英文页面和英文答案为准。

调查发现

异常不是普通人类论坛发帖，而是罕见组合：Agent actor + saidit_post + details.content_source。该组合在数据中只出现在三条 SaidIt posts 中。

使用的可视化方法

  • 先建基线 用条形图和比例条先定义正常行为，再判断异常。
  • 时间背景 用小时密度把异常帖放进全量事件流和病毒诱饵窗口中比较。
  • 矩阵聚合 用部门矩阵概括组织传播，避免把密集网络画成毛线球。
  • 按需查看细节 点击图中标记可查看 event id、timestamp、actor、target 和 raw JSON。
  • 联动推理 同一事件选择会联动终端序列、传播路径、来源和复发视图。
  • 避免误导 精确比较主要使用长度和位置，不用 3D、彩虹色或面积误导数量判断。

方法流程

工具与可复现性

构建和验证该可视分析系统所用工具

最终 rebuild 是一个自包含的浏览器端可视分析系统。提交页不依赖 Tableau、Vega-Lite 或 D3 运行时；旧的 D3 原型只作为开发过程文件保留，不是正式评审路径。

界面实现

HTML、CSS、原生 JavaScript 和自定义 SVG 渲染，用于联动视图、tooltip、筛选、图片放大和 URL 状态保持。

数据管线

Python rebuild/extract_data.py 解析官方 MC2 data.json 与 org_chart.json，导出 mc2_viz_data.json 和 .js。

质量检查

Playwright / playwright-core 和 Microsoft Edge 用于截图、交互验证、布局检查和统计图放大测试。

正式表格中的 Tools Used 可写：HTML/CSS/JavaScript、custom SVG、Python data extraction、PNG statistical figure generation、Playwright/Microsoft Edge verification、Git/GitHub Pages hosting。
